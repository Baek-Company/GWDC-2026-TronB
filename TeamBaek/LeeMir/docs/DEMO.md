# 발표 후 구현할 시연 시나리오

모든 사용자와 금액은 가상입니다. `data/personas.json`을 공통 입력으로 사용합니다.

1. 사용자님은 USDT 1,000을 보유하고 30일간 운용하며 200은 즉시 쓸 수 있기를 원합니다.
2. 어시스턴트는 기간, 유동성, 위험 선호를 확인하고 누락된 제약을 추가로 묻습니다.
3. 공식 출처를 가진 TRON 상품을 조회하고 참가 조건과 출구 조건을 검사합니다.
4. 동일한 입력에 대해 유동성을 더 남기는 계획과 조건에 맞는 수익 상품 비중을 높인 계획을 제시합니다.
5. 양쪽의 배분 금액, 기본 수익, 조건부 보상, 수수료, 예상 순수익, 위험을 비교합니다.
6. 사용자님이 계획을 선택하면 실제 금액, spender와 allowance 범위, 비용을 표시합니다.
7. 별도 확인과 지갑 서명 뒤 거래를 제출하고, 원래 txID의 실행·확정 상태를 추적합니다.
8. 원래 추정 가정과 관측 결과를 비교합니다. 과거 재생이면 시뮬레이션임을 계속 표시합니다.

현재 구현된 것은 데이터 조회와 계산 기반입니다. 위 전체 흐름이 완료된 제품은 아닙니다.
실행 경로와 대상 상품은 세부 주제의 시연 규칙을 확인한 뒤 선정합니다.

## 기본 실패 시나리오

- 공식 API 장애: 출처 조회 실패를 보여주고 현재 수익률을 임의 생성하지 않습니다.
- 자산 정밀도 초과: 반올림으로 전송 금액을 바꾸지 않고 입력 수정을 요청합니다.
- 조건에 맞는 상품 부족: 억지로 두 개를 추천하지 않고 부족한 조건을 설명합니다.
- 비용이 수익보다 큼: 순수익이 음수인 결과도 그대로 보여줍니다.
- 지갑 연결 거절/잠금: 사유를 보여주고 사용자님이 다시 연결하도록 합니다.
- 거래 타임아웃: 원래 txID를 조회한 후 처리하며 새 거래를 즉시 중복 제출하지 않습니다.

## 수익 계산 규칙

`shared/planning.ts`의 계산은 고정 APY를 가정한 수학적 예시 도구입니다.
기본 수익 = 원금 × ((1 + APY)^(일수/365) - 1).
보상 수익 = 원금 × 보상 APR × 일수/365.
순수익 = 기본 수익 + 보상 수익 - 같은 기준 자산으로 환산한 전체 비용.
실제 인센티브의 기간/가격/자격/복리 규칙이 다르면 검증된 규칙으로 바꿔야 합니다.
원자산의 시장 가격 변화나 디페깅 손실은 이 단순 계산에 포함되지 않습니다.
